## 5.4 Authentication, RBAC and Multi-Tenancy

Authentication issues a short-lived JWT access token and a rotating refresh token; passwords are hashed with Argon2. RBAC is enforced by a FastAPI dependency that checks the required permission and sets the PostgreSQL session variable that drives Row-Level Security, so tenant isolation holds even if an application check is missed.

```python
# core/security.py  (illustrative)
def require(permission: str):
    def dependency(user: User = Depends(current_user), db=Depends(get_db)):
        if not user.has_permission(permission):
            raise HTTPException(403, "Forbidden")
        # bind tenant for Row-Level Security (defence in depth)
        db.execute(text("SET app.tenant_id = :t"), {"t": str(user.tenant_id)})
        return user
    return dependency

@router.post("/sales", dependencies=[Depends(require("sales.create"))])
async def create_sale(payload: SaleIn, db=Depends(get_db)):
    return await sales_service.create(db, payload)
```

## 5.5 Inventory and Point-of-Sale

The POS commits a sale locally first (offline-first), recording immutable `SALE`, `SALE_LINE`, `PAYMENT` rows and appending `STOCK_MOVEMENT` entries; stock-on-hand is computed as a fold over movements, never mutated in place, guaranteeing conflict-safe reconciliation (§4.6). Barcodes are generated (Code-128/EAN-13) and scanned via the device camera using OpenCV/native scanners.

```dart
// mobile: commit a sale offline, enqueue for sync (illustrative)
Future<void> commitSale(Cart cart) async {
  final sale = Sale.fromCart(cart)
    ..id = uuid.v4()               // client-generated → idempotent
    ..lamport = clock.tick()
    ..capturedAt = DateTime.now()
    ..status = SaleStatus.committed;
  await db.transaction(() async {
    await db.sales.insert(sale);
    await db.stockMovements.insertAll(sale.toStockMovements());
    await db.outbox.enqueue(sale.toSyncOp());   // deferred sync
  });
}
```

## 5.6 Multi-Currency and Tax

Every monetary write records `(amount, currency, base_currency, exchange_rate, rate_source, captured_at)` as exact `NUMERIC` values (§4.5.2). A `TaxRule` engine computes ZIMRA VAT (standard/zero/exempt) and presumptive tax [37], parameterised so rate changes are configuration, not code. Reports convert historical amounts using the rate captured at the transaction, preserving economic meaning under devaluation.

## 5.7 Offline Synchronisation Engine

The client outbox posts batched operations with a `since` cursor; the server deduplicates by UUID, orders by Lamport clock, appends immutable events and applies last-writer-wins to master data, then returns server-side changes since the cursor for the client to fold in. Delta-only transfer conserves mobile data.

```python
# contexts/sales/sync.py (illustrative server-side apply)
async def apply_ops(db, tenant_id, ops, since):
    applied = []
    for op in sorted(ops, key=lambda o: o.lamport):
        if await db.exists(op.uuid):        # idempotent dedupe
            continue
        if op.entity in IMMUTABLE_EVENTS:    # sales, payments, movements
            await db.append(op)
        else:                                # master data → LWW
            await db.upsert_if_newer(op)
        applied.append(op.uuid)
    server_ops = await db.changes_since(tenant_id, since)
    return {"applied": applied, "server_ops": server_ops,
            "cursor": now_cursor()}
```

## 5.8 ML/AI Subsystem

Training pipelines (in `ml/`) engineer lag, calendar, payday and holiday features, fit Prophet/XGBoost per product/category, backtest with rolling-origin cross-validation, and export the selected model to ONNX into a model registry. The inference service loads ONNX artefacts and serves forecasts, reorder points and Isolation-Forest anomaly scores over the API. The AI assistant retrieves the tenant's own figures (RAG) and passes them to the LLM for grounded explanation.

```python
# ml/train_forecast.py (illustrative)
def train_product_forecast(history: pd.DataFrame):
    m = Prophet(weekly_seasonality=True, yearly_seasonality=False)
    m.add_country_holidays(country_name='ZW')
    m.fit(history.rename(columns={'date':'ds','qty':'y'}))
    metrics = rolling_origin_backtest(m, history)   # MAPE, RMSE, MAE
    onnx_path = export_onnx(m)
    registry.register(onnx_path, metrics)
    return metrics
```

## 5.9 Reporting, Documents and Notifications

Invoices, quotations, purchase orders, delivery notes and receipts render to PDF (server-side templating) and to printable receipt formats; financial statements (P&L, cash-flow, balance sheet) export to Excel. Notifications dispatch through pluggable SMS and email adapters and Firebase Cloud Messaging for push, queued via Redis so the request path stays fast.

## 5.10 Web Dashboard and Mobile UI

The React dashboard implements KPI widgets, interactive charts and AI insight cards with dark mode and responsive layouts; the Flutter app delivers the offline POS, inventory and sync UX. Both consume the same OpenAPI contract, guaranteeing parity.

## 5.11 Continuous Integration

GitHub Actions runs, on every push: linting, backend `pytest` (unit + integration against a Postgres service container), Flutter and web tests, an OpenAPI-contract check, and container-image builds. This enforces the "test & integrate" gate of the iterative process (§3.3) and NFR7.

```yaml

    steps: [ {uses: actions/checkout@v4}, {run: npm ci && npm test} ]
```

## 5.12 Challenges and Resolutions

| Challenge | Resolution |
|---|---|
| Conflict-free offline merge of financial data | Event-sourced immutable ledgers + UUID idempotency + Lamport ordering (§4.6) rather than general CRDTs |
| Preserving value under currency volatility | Transaction-time rate capture with exact `NUMERIC` (§4.5.2) |
| LLM hallucination in advice | RAG grounding over tenant data with tenant-isolated retrieval (§4.7) |
| Short, sparse series for forecasting | Prophet/XGBoost baselines over deep learning; backtesting to avoid over-fitting (§2.5) |
| Tenant-data leakage risk | RLS at DB layer in addition to application RBAC (§4.8) |
